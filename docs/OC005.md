# OC-005: simultaneous multi-axis interpolation validation

Implemented September 10, 2026. OC-003 validated the frozen logarithmic interpolator by withholding one axis (angle, temperature or field) at a time. OC-004 queries that same interpolator off-grid in temperature, field and angle **simultaneously** (21 K, the pack's own field magnitude, a mapped angle), and its own [A9 assumption](OC004.md#physical-model-and-assumptions-a1a11) flagged that simultaneous multi-axis error as never separately validated. OC-005 is that validation: one fold withholds planes along all three axes at once and reports errors stratified by how many axes are off-grid for each scored point, so the three-axis stratum is the direct analogue of an OC-004 query.

## Run and reproduce

```bash
# Save a complete run record; use a new output filename for each run.
cargo run --release --offline -- material-validate benchmarks/measured/oc-005.json \
  --output runs/oc-005-2026-09-10.json

# Print the full JSON report without saving a file.
cargo run --release --offline -- material-validate benchmarks/measured/oc-005.json --json

# Re-confirm OC-003's own suite is unaffected by the schema/checker changes this required.
cargo run --release --offline -- material-benchmark --json
```

`material-validate` exits successfully (0) only when `interpolation_validation_status` is `PASS`. This run's status is `FAIL` (see below), so the CLI exits 1; the full record is still written and printed. Both invocations above ran in approximately 0.15–0.16 s of wall time (dominated by process/cargo startup on an already-built release binary); the record's own measured `elapsed_ms` is 5.33 ms.

## Design

**Why multi-axis.** Every OC-003 fold holds one axis fixed on withheld nominal planes while the other two stay on the training grid. OC-004's query point (21 K, the local pack field, a mapped angle) is off-grid on all three axes at once — nothing in OC-003 scores that configuration directly.

**Withheld planes.** The single `multi_axis_planes` fold withholds nominal temperature 25 and 35 K; nominal field 1.5, 3.0 and 7.0 T; and 21 nominal angles from 5° to 175°. Training keeps the remaining 3 (temperature) × 4 (field) × 22 (angle) nominal grid — 264 measurements — under the dataset's declared cell spans (10 K, field ratio 2.5, 10°).

**Boundary rule, generalized.** OC-003's single-axis boundary rule is generalized as: a removed point is an unscored boundary omission if some axis *not* withheld for that point sits on that axis's own nominal boundary (its interpolation support would be one-sided regardless of the multi-axis holdout). Every other removed point strictly inside the non-withheld axes' bounds is scored and stays in the coverage denominator even if unsupported.

**Strata.** Each scored point is classified by how many of its three nominal coordinates lie on a withheld plane — one, two or three off-grid axes — and each stratum reports its own count, coverage, P95, worst and worst-positive relative error, alongside the same metrics for the whole fold. The three-axis stratum, where temperature, field and angle are all off-grid simultaneously, is the one that stands in for an OC-004 query; that is why `stratum_acceptance` places its own additional gate on that stratum's worst positive (overprediction) error specifically, separately from the whole-fold acceptance gates OC-003 already used.

## Three-axis stratum vs. the 0.10 gate

`stratum_acceptance.three_axis_max_positive_relative_error` = 0.10 (10.000%) (`benchmark.stratum_acceptance`, from the frozen case). Observed three-axis stratum worst positive (overprediction) error: **8.637%** (`folds[0].strata[2].max_positive_relative_error`) on 126 points, all covered — 1.363 percentage points under the gate.

**This specific gate is satisfied.** The pre-declared consequence (which is written only in terms of the three-axis stratum's worst *positive* error) is not triggered.

One further number is stated here because it is not gated and could otherwise pass unnoticed: the three-axis stratum's P95 relative error is 10.956% (`folds[0].strata[2].p95_relative_error`), above the 10% P95 limit that the whole-fold acceptance applies (and that the whole fold meets at 7.317%). If the OC-004-analogue stratum were held to the whole-fold P95 gate on its own, it would not meet it. This is consistent with the coarser-grid proxy interpretation below and is part of why the fold's overall status is `FAIL`, not a reason to relax any gate.

That is a separate question from the fold's overall status: the whole-fold `acceptance.max_relative_error` gate (20%, unchanged from OC-003's acceptance block) is exceeded by the whole-fold worst error (25.034%, an underprediction, in this same three-axis stratum), which is why `folds[0].status` and the top-level `interpolation_validation_status` are both **FAIL**. That failure is driven by the general worst-error gate on an underprediction, not by the overprediction-specific stratum gate the consequence rule is written against.

## Interpretation

- **Coarser training grid than the full model, so this is a conservative proxy.** This fold trains on only 264 of the dataset's 1,505 measurements (a 3×4×22 grid with two temperature, three field and 21 angle planes removed), while OC-004's live queries run against the full 1,008-cell / 6,048-tetrahedron model built from all 1,505 rows. Removing whole planes strips support the live interpolator retains, so OC-005's measured errors should overstate, not measure directly, the error the live model makes at an OC-004-style off-grid query.
- **Same specimen, development validation.** All data is SP066 / SCS12050-AP M3-1386-3, the same specimen OC-003 already used; this is not an independent-batch or reserved-sample test, and the description states the interpolator was not retuned on this fold under any outcome.
- **The three-axis stratum, not the whole fold, is the OC-004 analogue.** The whole-fold FAIL is real and disclosed, but the number the decision rule and OC-004's A9 assumption should be read against is the three-axis stratum's worst positive error (8.637%), which passed its own gate.
- **The failure is a single hard point in a known feature, not a systematic overprediction problem.** The whole-fold FAIL traces to one point at the dataset's known hardest angular feature (the ~90° ab-plane peak at 35 K, 7 T), underpredicted by 25.034% when all three axes are withheld around it. An underprediction is conservative for a current margin, but it still exceeds the fold's own declared 20% worst-error limit, so it cannot be waved away as harmless.

## Consequence outcome for OC-004's budget

Stated plainly, without softening either way: the pre-declared consequence is **not triggered**. The three-axis stratum's worst positive relative error (8.637%) stays under the declared 0.10 gate, so under the frozen decision rule, **OC-004's declared `interpolation_overprediction_budget` (0.10) is retained**, with the observed value quoted here for the record: 8.637%, 126 covered points, 100% coverage.

This does not mean the multi-axis validation passed outright: `interpolation_validation_status` is **FAIL** for this fold, because its whole-fold worst error (25.034%, an underprediction at the same 35 K/7 T/~90° feature) exceeds the fold's general 20% worst-error gate — a real, disclosed limitation of this validation that is independent of, and does not by itself invalidate, the overprediction-budget number OC-004 depends on.

## Limitations

- One research specimen (SP066): a 1 mm patterned bridge, not a manufacturer batch guarantee or full-width tape qualification (`dataset.metadata.limitations`).
- Applied-field data includes the specimen's self-field response; no intrinsic local Jc(B) law or coupling to OC-002 is established by this fold.
- Maximum Lorentz-force angle geometry only; no reflection symmetry, arbitrary azimuth or extrapolation is assumed.
- This is a withheld-plane development validation, not a statistical confidence interval or a guaranteed lower current bound (top-level `limitations`).
- The three-axis stratum's coarser training grid makes its errors a conservative proxy for OC-004's live off-grid query error, not a direct measurement of it — see Interpretation above.
- Engineering current margins, thermal, mechanical, quench and manufacturing acceptance remain `NOT_EVALUATED` (`engineering_status`).

## Next engineering work

Investigate whether a training grid closer to the full 1,008-cell model (fewer simultaneously withheld planes, or a held-out point set instead of held-out planes) narrows the gap between this fold's conservative proxy and OC-004's actual live-model error at its specific query points. Extend the same three-axis stratification to the reserved 45 K challenge dataset once a multi-axis challenge case is warranted. Revisit the 35 K/7 T ab-plane peak specifically — it is now responsible for the worst logged error in both OC-003 (single-axis, 19.967%) and OC-005 (multi-axis, 25.034%) — with additional measurements or a locally refined interpolation cell, before treating either number as a stable characterization of that feature.
