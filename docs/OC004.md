# OC-004: coupled conductor–geometry screening

Implemented September 9, 2026. This benchmark connects the OC-002 finite-cross-section racetrack field evaluator to the OC-003 measured SuperPower bridge law, at explicit tape positions and orientations, to produce a screening operating-current margin under declared assumptions. It is **not** a production operating-current limit. `conductor_qualification_status` is always `INCONCLUSIVE` and `engineering_status` is always `NOT_EVALUATED` in this build.

## Run and reproduce

```bash
# Embedded case and embedded reference; no Python needed to run.
cargo run --release --offline -- coupled-benchmark

# Preserve all inputs, per-tape/per-candidate detail, convergence and identities.
cargo run --release --offline -- coupled-benchmark --output runs/oc-004.json

# Explicit files, useful when developing a separately identified case.
cargo run --release --offline -- coupled benchmarks/coupled/oc-004.json \
  --reference benchmarks/coupled/oc-004.reference.json --json

# Override the case's own declared quadrature orders (exactly two, increasing, 2..=24).
cargo run --release --offline -- coupled-benchmark --orders 18,24 --json

# Reproduce the independent reference with Python and NumPy, never the Rust kernel.
# The destination must not already exist.
python3 tools/reference_oc004.py --case benchmarks/coupled/oc-004.json \
  --output runs/oc-004-reference-reproduced.json --orders 24,48 --evaluated-current-a 870.0

# Reproduce the archived-workbook assumption audit (fixed output path; refuses to overwrite).
python3 tools/audit_oc004_material_assumptions.py
```

Omit `--offline` only if the Rust dependency cache needs populating. The checked reference was generated with Python 3.14.4 and NumPy 2.3.5. Python is an independent development/reference tool; the product evaluator and CLI remain Rust.

The `coupled`/`coupled-benchmark` commands exit successfully (0) only when `numerical_status` is `PASS`, `coverage_status` is `PASS` and every current candidate's screening status is `PASS`. A determined `FAIL` candidate, missing reference evidence, unresolved convergence or coverage gaps all produce a nonzero exit; the full JSON diagnostics are still written/printed for a completed run. Malformed inputs, stale references and numerical work-limit errors fail explicitly. Files are never overwritten. Every human-readable report ends with the standing disclaimer: "Screening current allowance under declared assumptions ONLY; this is NOT a production operating-current limit." The egui app is not part of this benchmark; OC-004 is available through the headless API and CLI only.

## Physical model and assumptions (A1–A11)

**A1. Field source.** A homogenized racetrack pack (`optcoil_model::magnetics::Racetrack`) with uniform tangential volume current, `ampere_turns = total_turns × I_op` (600 × I_op). Unit-ampere-turn field is evaluated once per point per order and scaled linearly per candidate, using the evaluator's tested linearity property. No inter-pancake spacer gaps, screening currents, redistribution or iron.

**A2. Applied-field mapping (self-field consistency).** The measured bridge's `Ic/w` at applied field B is used as the tape's allowed sheet current at the pack field B, via the thin-strip self-field argument: `K_allowed(B_pack, theta) := (Ic/w)_bridge(T, |B_pack|, theta)`. The diagnostic A2(i) residual scale at the limiting tape (`own_tape_edge_field_scale_t`) was 0.1198 T at 520 A, 0.0949 T at 700 A and 0.0786 T at 870 A.

**A3. Self-field ratio diagnostic.** `r = mu0 × K_used / (2 × |B_query|)` is reported for every width point. The declared limit (0.1) applies only to the *limiting point of the limiting tape* of an otherwise-PASS candidate: `limiting_self_field_ratio` was 0.0191 (520 A), 0.0112 (700 A) and 0.0075 (870 A) — all far under 0.1, so this gate never demoted a candidate. The diagnostic `max_self_field_ratio` over all determined points was 0.2365 for every candidate identically, because it is dominated by a low-field, clamp-basis point whose query field is fixed at 1.001 T regardless of the operating current.

**A4. Tape frame and orientation.** Lab frame as OC-002; `tape_normal: radial` (pancake/layer winding). Only `radial` has a frozen case; `axial` is implemented and unit-tested but not exercised by this benchmark.

**A5. Angle mapping.** Period-180° field-reversal folding, then the `minimum_of_mirror_pair` policy over {theta, 180−theta}. Evidence from the [assumption audit](../benchmarks/coupled/oc-004.assumption-audit.json) against the archived workbook (Set T in {20,25,30,35,40} K): Representation: a folded angle is queried first as written and, if that representation lies outside the measured angular hull, as its period-180 equivalent `theta − 180°`; the measured 0° plane sits at Hall angles between −1.7° and +1.5° and the 180° plane between 178.5° and 179.6°, so orientations within about a degree of perpendicular are covered only in one representation or the other. This uses the same declared field-reversal symmetry and is not extrapolation (model id `coupled-racetrack-pack-bridge-law-screening/v2`; no OC-004 point needed the fallback, and every number in this document is unchanged under it — OC-007 sampled such points on the pack faces near the axial-field null line).
- Field reversal, 0° vs 180°: 100 (T, field) pairs, worst +4.378% at (20 K, 8 T), median 0.950%, p95 2.404%.
- Field reversal, θ+180° vs θ for θ in 5–60° (via the 185–240° continuation rows): 1200 pairs, worst +3.588% at (20 K, 7 T, 5°), median 0.384%, p95 1.687%.
- Mirror asymmetry (a vs 180−a): the OC-004 contract cites a worst observed asymmetry of 16.6% at 40 K, 2 T, 84° vs 96°, drawn from the same archived workbook; this specific statistic is not separately recomputed by `tools/audit_oc004_material_assumptions.py`, which is flagged here rather than re-derived.
Along-current exclusion: observed `max_along_current_fraction` was 0.02383 at every candidate, against the declared limit of 0.2 — no point was `along_current_excluded`.

**A6. Temperature.** 21 K, strictly interior to the dataset's nominal 20–40 K span (nominal 20 K rows are measured at 19.98–20.00 K).

**A7. Width.** 5-point Gauss–Lobatto quadrature; the run record's `width_rule` nodes are `{-1, -0.65465, 0, +0.65465, +1}` with weights `{0.05, 0.27222, 0.35556, 0.27222, 0.05}` (summing to 1). `I_min` (the screening quantity, min over width) and `I_strip` (the parallel-strip estimate) are reported per tape; see the results table.

## Kernel revision: resolving the near-face convergence failure

The first run, at the frozen case's declared quadrature orders `[10, 14]`, returned `numerical_status: INCONCLUSIVE`. The `field_refinement` check (the Rust evaluator's own order-10-vs-14 change, scaled to each candidate) reached **1.684392704e-2 T** against the declared **2.500000000e-3 T** limit: 544 of the 900 sampled points at the 870 A candidate exceeded the gate, all at tape centers within roughly 0.05–1.05 mm of a radial pack face (turns 1, 2, 3, 5, 10 and 190, 195, 198, 199, 200 of 200); turns 20–180 stayed far under the gate. `reference_refinement` (the Python reference's own order-24-vs-48 change) reached **6.201696909e-3 T** against a **1.000000000e-4 T** limit. Because `independent_comparison` requires both refinement checks to PASS before it can itself PASS or FAIL, it and therefore `numerical_status` collapsed to `INCONCLUSIVE` regardless of the raw comparison, which itself already missed its own gates (max field error 1.1484e-2 T vs a 1e-3 T limit; max angle error 0.07847° vs a 1e-4° limit; max capacity relative error 2.019e-3 vs a 1e-5 limit). `coverage_status` stayed `PASS` and the per-candidate screening statuses (520 A PASS, 700 A PASS, 870 A FAIL) were unaffected — this was a numerical-convergence failure, not a physical one. This run and its reference are preserved unmodified as `runs/oc-004-development-2026-09-09.json`.

**Cause.** In `crates/optcoil-physics/src/racetrack.rs`'s near-cell branch, each near-face octant is tiled into three Duffy pyramids. The pyramid whose dominant axis is the pack's short (radial or axial) extent has its two *transverse* coordinates scaled by the pack's long, along-path extent, so the mapped `1/r³` kernel develops a peak whose relative width in each transverse coordinate equals the short/long extent ratio — for a tape center about 0.15 mm from a radial face inside a cell whose along-path extent is centimeters, that ratio is of order 1e-2 to 1e-3, well below what a 10–14 node plain Gauss rule resolves. OC-002's exterior probes never sit this close to a source-cell face; OC-004 deliberately samples tape centers at or inside the pack, which triggers this failure mode routinely. The independent Python reference's Duffy triangles have the identical structure and needed the same fix.

**Fix.** Grade the transverse (v, w) Gauss rules per Duffy pyramid, reusing the same geometric-panel construction (`near_radial_rule()`) already used for the radial u coordinate of exterior points: `r_v = |extent[dominant]| / |extent[second]|`, `r_w = |extent[dominant]| / |extent[third]|`, each selecting a graded rule that reduces to the plain rule once the ratio reaches 0.25. The dominant-axis u rule, the `1/r³` kernel and separated-cell handling are unchanged. The same grading was applied to the independent Python reference's Duffy triangles (`tools/reference_oc004.py`'s `field_graded`). Both model identities were bumped accordingly — `racetrack-uniform-volume-duffy-gauss-graded/v2` (Rust) and a `...-duffy-gauss-graded+...` method string (the reference) — at the **same declared quadrature orders as before** ([10, 14] Rust; [24, 48] reference): this is a quadrature-panel change, not a higher order. One implementation detail is disclosed rather than hidden: the source cells of the two curved ends are parameterized by azimuth, so for those cells the along-path extent entering the grading ratio is in radians while the radial and axial extents are in metres, and the ratio differs from the physical aspect ratio by the local radius (about 0.2 m). Because the panels are geometric, this shifts only where the first panel boundary falls, not whether the peak is resolved: the near-face convergence test reaches |B14 − B10| of at most 4e-13 T per ampere-turn across its 12 tested points, including the bend apex. A metric-consistent ratio is a follow-up refinement, not a correctness fix.

**Review follow-up: scoping the transverse grading's roundoff exception correctly.** A later review found that the fix above reused `near_radial_rule`'s low-end carve-out (`relative_distance <= 128*f64::EPSILON`, sized for the *u* coordinate's distance-to-boundary meaning) for the *v*/*w* transverse ratios too. That carve-out is wrong there: a legitimately tiny transverse extent ratio is exactly where the near-face peak is narrowest and grading matters most, not a case to skip. `evaluate()`'s transverse calls now use a dedicated `near_radial_rule_for_ratio` with no low-end exemption (ungraded only at or above the same 0.25 threshold), matching the independent Python reference's `graded_unit_rule` exactly. Removing the exemption naively was not safe on its own, though: at real OC-004 sample points a tape's Gauss–Lobatto width edge lands, after the tape-center/offset arithmetic, a few ULPs shy of the pack's own face along one axis (e.g. `z = 0.017999999999999995` against `axial_height_m/2 = 0.018`), and grading that near-zero *extent* with no floor drove the panel count past `MAX_SAMPLES_PER_PROBE`. `evaluate()` now checks `extent[dominant]` itself against the cell's own extent along that same axis before computing either ratio; only when that offset is roundoff-scale (the observer sits essentially ON the face along `dominant`, up to floating-point precision) does it fall back to the plain rule there — its pyramid's `box_jacobian` already carries this same near-zero factor, so that corner's contribution is already negligible regardless of how finely v/w are resolved. The independent Python reference does not share this exact failure mode (it integrates the axial direction in closed form, so it never grades a third, out-of-plane coordinate), and needed no change for it; it was, however, extended to apply the declared A5 along-current exclusion it had previously always skipped — never actually triggered by this frozen `reference_subset`, whose maximum along-current fraction is ~7e-19, so the regenerated reference (`benchmarks/coupled/oc-004.reference.json`, SHA-256 `c6620ae08c555d540ba18acfbe6063192828db88a62937a22b1851d7ae23bf90`) still carries 89 `estimate` / 1 `lower_bound` points and 0 `along_current_excluded`. Re-running the full benchmark reproduced every screening status, utilization and reference-comparison figure above bit-for-bit (`kernel_evaluations` fell slightly, to 1,659,872,448, since the corrected check now short-circuits both transverse rules at once for a degenerate corner instead of only one); only the observed wall-clock timing changed, see below, which is consistent with ordinary machine-load variance on this shared laptop rather than added algorithmic work.

## Kernel revision v3: metric-consistent transverse grading ratio (OC-008 contract, Stage K)

**Cause.** The transverse grading ratio introduced above (`r_v = |extent[dominant]| / |extent[second]|`, `r_w` likewise) compares extents in each source cell's own coordinates. For the two curved parts, coordinate 0 is azimuth in radians while coordinates 1 and 2 (radial, axial) are metres, so whenever the ratio's numerator or denominator was the azimuthal extent, the value differed from the true physical aspect ratio by the local radius (~0.2 m on this pack) — already flagged as a follow-up, not a correctness fix, when v2 was introduced above.

**Fix.** `crates/optcoil-physics/src/racetrack.rs` gained `transverse_grading_ratio(part, radius_m, extent, dominant, other)`: straight cells are unchanged (every coordinate is already metres); for the two curved parts, whichever of `dominant`/`other` is axis 0 is first scaled by the observation point's own clamped source radius (`center[1]` from `Cell::project`) before the ratio is formed. The dominant-axis `u` rule, the kernel, separated-cell handling and the near-boundary roundoff exception are all unchanged (`FIELD_MODEL_ID` bumped to `racetrack-uniform-volume-duffy-gauss-graded-metric/v3`). The same conversion was applied to the independent Python reference's `field_graded` (`tools/reference_oc004.py`): its Duffy-triangle extent `e0` is scaled by the projected center's own radius before forming the short/long ratio on `"right"`/`"left"` cells only; `tools/reference_oc002.py` is untouched (its hash is pinned by the frozen OC-002 reference). A new unit test (`transverse_grading_ratio_is_unchanged_for_straight_cells_and_metric_corrected_for_arc_cells`) checks both cases directly, and the existing near-face convergence test now also asserts the arc-apex points converge at least as tightly as before (measured: |B14−B10| at most 4.309e-13 T pre-fix vs 4.289e-13 T post-fix across the six tested arc-apex points, both far under the test's 5e-9 T bound).

**Effect on the OC-004 reference.** Regenerating `benchmarks/coupled/oc-004.reference.json` with the fixed tool (`--orders 24,48 --evaluated-current-a 870.0`; old file preserved, SHA-256 `f68edfdf5736c7b07cf5d1b09e2611f645f88774443f745eec975db7a8d8ae4e` → new SHA-256 `afed78224b6c3ca420bd493bb6ee4e0943fb662f6f604887d20acba2da872ffe`) changes every one of the 90 stored points by an amount at the limit of double-precision roundoff, not a physically meaningful shift: max per-order unit-field vector difference **3.05e-20 T per ampere-turn**, max scaled-field vector difference **1.51e-14 T**, max folded-angle difference **1.14e-13°**, max `k_used_a_per_m` difference **2.33e-10 A/m** (relative **1.80e-15**), **0 of 90** points changed `basis`. This is expected: both the v2 and v3 transverse rules are already far inside their refinement gates (see below), so a different panel count converges to the same integral to roundoff, not a different one — the fix is a numerical efficiency/robustness correction (avoiding an azimuth-in-radians ratio that over-grades arc cells at this pack's sub-1-m bend radius), not a change to what is being computed.

## What this does not establish

- **No production operating-current limit.** Every PASS above is a screening allowance under declared assumptions, not a qualified operating current.
- **No width transfer.** `width_transfer.basis` is `none`: the allowance is derived from a 1 mm × 5 mm patterned bridge, not a measured full 12 mm tape, and no Jc nonuniformity across the width or batch variation is represented.
- **No batch coverage.** All measured data comes from one specimen (SP066 / SCS12050-AP M3-1386-3).
- **Multi-axis interpolation validation now exists, and it retains this benchmark's budget but is not an unqualified pass.** [OC-005](OC005.md) withholds all three axes simultaneously and scores its three-axis stratum — the direct analogue of an OC-004 query — at a worst positive (overprediction) error of 8.637%, under the 10% `interpolation_overprediction_budget` used here, so that budget is retained rather than flagged insufficient. OC-005's own overall fold status is nonetheless `FAIL` (whole-fold worst error 25.034%, an underprediction at the same 35 K/7 T ab-peak OC-003 already flagged, over OC-005's separate 20% general worst-error gate), and its training grid is coarser than the full model this coupling queries — so its numbers are a conservative proxy, not a measured bound, on this coupling's actual off-grid interpolation error.
- **No spacer gaps.** Zero inter-pancake gap is assumed; any real gap changes the local current density in the non-conservative direction.
- **No current sharing.** One tape per turn is assumed; parallel tapes and current redistribution are unmodeled.
- **No force-free component.** The material query uses total field magnitude with the transverse angle; a force-free (along-current) field contribution is not itself modeled, only excluded above `max_along_current_field_fraction`.
- **Mechanical, thermal, quench and manufacturing acceptance** are all `NOT_EVALUATED`.
