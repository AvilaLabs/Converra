# OC-017 — the `transverse_bound` along-current model (schema v6 / v3 / run v3)

**Status: implemented and tested; v6mx grid rerun launched. Results are
model-informed — bounded estimates are labeled `along_current_bounded`,
never clean measured-plane estimates.**

## The blocker

The measured `Ic(B,T,θ)` law is only valid in maximum-Lorentz geometry —
field in the tape's normal–width plane. When the local field picks up a
component along the transport direction (tape edges at arc stations), the
evaluator has no measured basis: `along_current_fraction > 0.20` →
`along_current_excluded` → INCONCLUSIVE.

On OC-012 v5mx, this was the *only* remaining INCONCLUSIVE class: 17
candidates, all at fractions 0.20–0.31 — modest tilts, clustered just
past the gate.

## The model — `limits.along_current_model: "transverse_bound"`

Opt-in, versioned, and bounded:

| Fraction `f = |B_t|/|B|` | Handling |
|---|---|
| `f ≤ 0.20` (declared limit) | unchanged — clean measured-plane estimate |
| `0.20 < f ≤ 0.50` (`ALONG_CURRENT_BOUND_CEILING`) | measured-law query still runs at **full field magnitude** and the **transverse-plane angle**; point labeled `along_current_bounded` |
| `f > 0.50` | `along_current_excluded` — unchanged; the bound's footing ends at the force-free/flux-cutting regime |

Declared assumption: a field component along transport degrades Ic no
more than an equal transverse component. Both queried quantities lean
conservative — full magnitude overcounts vortex density (the
along-current part is Lorentz-force-free), and the transverse-plane angle
is the orientation the dataset supports. Rotating-probe literature
consistently shows Ic *rising* as B tilts toward J, so the same-magnitude
transverse query is a plausible bound — but it is a bound, not a
measurement, and the record says so on every such point.

## Version chain

- `optcoil-coupled-search/v6` — `limits.along_current_model` permitted
  (only `"transverse_bound"`); v6 inherits v5's self-field correction and
  v3+ feature gates.
- `optcoil-coupled-conductor/v3` — the generated conductor case carries
  the declared model.
- `optcoil-coupled-run/v3` — `PointBasis::AlongCurrentBounded` plus the
  `along_current_bounded` point counter; bounded points count as
  determined for candidate capacity (they carry a queried `k_used`), but
  stay visibly labeled.
- Reference checker (`tools/reference_oc004.py`) mirrors the bound with
  the same gate ordering and emits `along_current_bounded`; method ids
  `+along-current-transverse-bound/v1` (alone or stacked on
  `uniform-transport-self-field/v2`) are pinned exactly.

## Tests

- `transverse_bound_marks_over_limit_along_current_points_on_a_real_run`
  — real `run_coupled_case` pipeline on a tight-bend fixture whose arc
  station produces fractions ~0.20–0.22: without the model, points are
  `along_current_excluded`; with it, they become `along_current_bounded`
  carrying queried values.
- `transverse_bound_still_excludes_points_above_the_model_ceiling` —
  fraction 0.6 stays excluded even with the model declared.
- Model-crate tests: v6 parses/validates, v5 rejects the field, unknown
  model strings rejected, generated case carries conductor schema v3.

## What it can and cannot claim

A candidate whose margin rests on `along_current_bounded` points is
*model-informed* — the same epistemic tier as the OC-016 extension. The
label is part of the record; reporting it as a clean measured-plane PASS
misstates the evidence. When angular-dependent high-field data arrives
(the pending UNIGE request), the 0.20 gate itself can be revisited with
measurements rather than a bound.
