# OC-007: coupled cost search over pack geometry under a fixed field requirement

Both frozen cases were run September 10, 2026. This is the first end-to-end experiment of the product thesis on measured conductor data: an exhaustive discrete search over permitted racetrack pack geometry (turns along normal x tapes along width) that keeps the OC-004 coupled screening margin as its physical gate, under an unchanged 0.9 T bore-field requirement, with a separate independent acceptance recomputation. Prices are synthetic and declared; the result reported below is a **modeled saving under a screening model**, never a production claim.

**Both cases were re-run the same day under kernel v3** (the OC-008 contract's Stage K metric-consistent transverse-grading fix; see "Kernel v3 re-validation" below): every status, the optimum, the baseline and the saving figure reported throughout this page are unchanged, and the earlier v2-kernel run records stay in `runs/` unmodified as superseded history with identical results.

## Run and reproduce

```bash
# Frozen primary case (OC-006 low-field dataset), full record to a file and to stdout.
cargo run --release --offline -- coupled-search benchmarks/coupled/oc-007.json \
  --threads 5 --output runs/oc-007-<date>.json --json

# Embedded primary case via the dedicated subcommand (equivalent to the command above).
cargo run --release --offline -- coupled-search-benchmark --threads 5 --json

# The pre-declared original-dataset control (contract D1); no dedicated CLI
# subcommand exists for it (a library-only run_oc007_control() does), so it
# is run as an explicit case file like any other:
cargo run --release --offline -- coupled-search benchmarks/coupled/oc-007-control.json \
  --threads 5 --output runs/oc-007-control-<date>.json --json
```

`coupled-search`/`coupled-search-benchmark` exit 0 only when `search_status` is `PASS` **and** the embedded `acceptance.agreement_status` is also `PASS`. `search_status` is `PASS` only when a passing candidate exists **and** the acceptance module's refined-plan gate (below) holds for both the baseline, when it itself PASSed, and the selected optimum; otherwise it is `INCONCLUSIVE`, never silently `PASS`. `--threads` may only lower the case's own declared `execution.max_threads` (5). The full JSON record — every candidate including pruned/failing ones, the best, the baseline, the saving, and the acceptance recomputation including the refined-plan detail — is written/printed regardless of exit code. Files are never overwritten; each run below took roughly 15.7 minutes, so a re-run needs a fresh output filename.

**Coarse pruning rule.** A candidate is conservatively pre-screened on a coarse subset: stations {`arc_apex`, `straight_center`} x turns {1, round(0.5n), n} x tapes {1, last} x width indices {0, 4} (24 points, all 5 width points' worth of station/turn/tape combinations sampled at the two edge width indices). A coarse FAIL prunes the candidate — recorded with its failing point — **only if every coarse point's own order-vs-order refinement change, scaled to the candidate's ampere-turns, is itself within the declared refinement gate** (0.0025 x 1.0 T); an unconverged coarse point can't be trusted to prune, so the candidate proceeds to the full plan instead and `coarse_refinement_unresolved` records why. A coarse PASS or INCONCLUSIVE always proceeds to the full plan; only the full plan can produce a candidate PASS.

**Refined-plan rule (acceptance-only, contract §9.4, amended).** For the selected optimum and the baseline, when each was itself PASS on the full search plan, the acceptance module re-evaluates screening on a finer plan: 10 stations (the search's own 4 plus 6 declared additional ones — arc azimuths 15/30/60/75 deg and straight x = 0.15/0.25 m) and turn indices equal to the **union** of the coarse search plan's own turn indices with every 5th turn from the start and the near-face turns {1, 2, 3, n-2, n-1, n} — so the refined minimum is always taken over a superset of the coarse points (shortfall >= 0 by construction); the step widens past 5 only as far as needed to respect the shared 64-index sampling cap (only `n = 300` actually widens it, to step 6). All tapes, all 5 width points. Gates: the candidate must keep PASS status on the refined plan, and refined `min_allowed_screening_a` must be at least `(1 - 0.02)` times the coarse plan's own (independently re-verified) minimum; a shortfall beyond 2% or a lost PASS sets `search_status: INCONCLUSIVE` for that run, never silently reconciled.

## Control case outcome

The control run (original `robinson-superpower-ap-v3` dataset, `low_field_clamp_t 1.001`) reproduces the **search-level** candidate table, optimum, costs and savings figure **identically** to the primary run: same 15 statuses, same optimum (index 2, 120x4, $41,513.13), same baseline ($50,541.41), same saving ($9,028.28 / 17.863%). Only the basis counts of non-limiting points differ, as pre-declared: the optimum candidate has 1,120 `estimate` / 0 `lower_bound` points on the primary (low-field) dataset versus 1,100 `estimate` / 20 `lower_bound` on the control (original) dataset — points below 1.001 T that the low-field dataset evaluates directly and the original dataset can only serve via its clamp. **The pre-declared search-level expectation is therefore met.**

The control's **acceptance-level** result is **not** identical, however: `search_status: INCONCLUSIVE` and `acceptance.agreement_status: FAIL`. The baseline's refined-plan re-check still PASSes (identical numbers to the primary case: 0.543% shortfall, PASS). But the **optimum's** refined-plan re-check comes back `INCONCLUSIVE` (not PASS) on the control case: exactly **2 of 6,400** refined-plan points are `Unsupported` — station `arc_75`, turn 70, tapes 2 and 3, |B| = 0.2876 T at a folded angle of 179.34 degrees (mirror representation 0.66 degrees). Below the original dataset's 1.001 T clamp, the clamp query at 1.001 T and 179.34 degrees falls outside the 180-degree side of that dataset's 1 T angular hull, and the equivalent -0.66 degree representation falls about 0.02 degrees outside the 0-degree side of that hull (measured there at roughly -0.64 degrees), so the point is unsupported in both representations under the original dataset. The low-field dataset (the primary case) has no such gap because it evaluates this point directly at its actual 0.29 T — well above its own 0.0501 T clamp, so no clamp fallback and no angular-hull edge case is triggered.

This is a genuine coverage limit of the original dataset at a low-field, near-perpendicular, **non-limiting** point (the candidate's own screening status and cost are unaffected: `min_allowed_screening_a` on the control's refined plan is still 1090.79 A at the unchanged limiting point, `arc_apex`/tape4/turn20/w4) — and it is exactly the gap OC-006 was built to close. **Both results are reported plainly, without reconciling them:** the pre-declared search-level expectation is met; the acceptance-level expectation (which is not itself pre-declared to match, but which the refined-plan mechanism is designed to catch) is not met on the control case, and the reason is diagnosed and disclosed rather than patched around.

## Independent-review findings and how each was addressed

Four findings from an independent review of the OC-007 implementation, incorporated before either frozen case ran:

**Reference checker defect (§9.1).** `coupled.rs`'s reference comparison previously skipped the capacity check entirely when either the Rust or reference `k_used_a_per_m` was `null`, so a reference with every K value stripped (basis strings intact) would still report `independent_comparison: PASS`. Fixed: the comparison now requires, for every reference point whose Rust basis is determined (`estimate`/`lower_bound`), that both K values be present and finite; a gap sets `capacity_missing: true` and fails the check. `ReferenceComparison` gained `compared_capacity_points`/`capacity_missing`. `COUPLED_CHECKER_ID` bumped to `coupled-refinement-reference-and-declared-margin-screening/v2`. Test: `coupled::tests::nulled_reference_capacity_values_fail_independent_comparison`. OC-004 itself is unaffected: re-running `coupled-benchmark` under the v2 checker reproduces every OC-004 number bit-for-bit, with `compared_capacity_points: 90`, `capacity_missing: false` (its frozen reference carries all 90 K values) — see [OC-004](OC004.md).

**Acceptance units (§9.2).** `search_acceptance.rs`'s bore-field agreement check previously compared a per-ampere-turn field difference directly against a tesla-scale tolerance, which would silently pass almost any real discrepancy. Fixed: the check now scales the difference by the candidate's own `ampere_turns_a` before comparing (`field_absolute_error_t`). Test: `acceptance_scales_the_field_discrepancy_by_ampere_turns_not_a_bare_tesla_tolerance` plants a 1e-6 T/A-turn discrepancy at NI = 4e5 A-turn (a genuine 0.4 T error) and confirms it now FAILs.

**Pruning convergence (§9.3).** `coupled_search.rs`'s coarse pre-screen could previously prune a candidate on a coarse-point FAIL without checking whether that point's own field was itself numerically converged. Fixed: each coarse point's order-vs-order refinement change, scaled to the candidate's NI exactly as the full-plan check does, is compared against the declared refinement gate; an unconverged coarse point prevents pruning, and `coarse_refinement_unresolved` records why. Test: `unconverged_coarse_point_prevents_pruning_and_forces_the_full_plan`. In the actual run, all 6 pruned candidates converged on the coarse plan (`coarse_refinement_unresolved: false` throughout), so this rule was never needed to override a pruning decision here — it stood as a guard that did not trigger.

**Sampling refinement in acceptance (§9.4).** The coarse sampling plan (15 of n turns, 4 stations) cannot by itself establish a candidate's true weakest location. Added: the `refined_plan` case field (10 stations, denser turn selection, 0.02 shortfall gate) and the acceptance module's refined-plan re-evaluation described above. This is the finding whose actual behavior in the real run turned out to matter most: it is what caught the control case's 2-point coverage gap (above) that the coarse plan's original 15-of-n-turns sampling never queried.

**Two further fixes made after the initial build, before either case was run:**

1. **Refined-plan turn-index rule widened to a union (amended §9.4).** The refined plan's turn selection is now the **union** of the coarse search plan's own turn indices with every 5th turn and the near-face turns {1, 2, 3, n-2, n-1, n} (`optcoil_model::coupled_search::refined_plan_turn_indices`; the step widens past 5 only as far as needed to respect the shared 64-index sampling cap — only `n = 300` actually needs step 6). This guarantees the refined minimum is always taken over a strict superset of the coarse points, so a shortfall can never be negative by construction. Test: `refined_plan_union_tests::refined_plan_is_a_superset_of_the_coarse_plan_and_respects_the_index_cap`.
2. **Angle-query period-180 fallback (`query_angle_with_clamp`, `query_k` in the reference tool).** Before declaring a point unsupported, the angle query now also tries the point's period-180 equivalent representation (`theta - 180`) before giving up. This resolved the reason the *optimum's own* refined plan was `INCONCLUSIVE` before this fix: 48 of 6,400 refined points on the 120x4 optimum sit on the pack faces near the axial-field null line (turns 65-75), about 5.2 T at 179.0-179.8 degrees from the tape normal — the measured 0-degree plane sits at Hall angles between -1.7 and +1.5 degrees and the 180-degree plane between 178.5 and 179.6 degrees, so orientations within about a degree of perpendicular are covered only in one representation; the `[0, 180)` representation alone fell outside the hull, and all 48 points resolve under the equivalent representation. This is the already-declared field-reversal symmetry (contract A5), not extrapolation. `COUPLED_MODEL_ID` is now `coupled-racetrack-pack-bridge-law-screening/v2`; the OC-004 reference was regenerated under the same fix in the Python reference tool (every stored value byte-identical, only the tool's own pinned source hash changed, new reference SHA-256 `f68edfdf5736c7b07cf5d1b09e2611f645f88774443f745eec975db7a8d8ae4e`), and OC-004's own statuses and numbers reproduce exactly under it. Test: `angle_representation_tests::angles_just_below_180_are_served_by_their_negative_representation`.

## Kernel v3 re-validation (2026-09-10, OC-008 contract Stage K)

`crates/optcoil-physics/src/racetrack.rs`'s near-face transverse grading ratio was corrected to compare physical lengths rather than mixed coordinates on the two curved winding-pack parts (one raw ratio coordinate is azimuth in radians, the other two are metres; the pre-fix ratio differed from the true physical aspect ratio by the local ~0.2 m bend radius, over-grading arc cells). `FIELD_MODEL_ID` is now `racetrack-uniform-volume-duffy-gauss-graded-metric/v3`; the kernel, dominant-axis rule and separated-cell path are unchanged. Full detail, including the OC-002/OC-004 re-validation this fix required first, is in [OC-002](OC002.md) and [OC-004](OC004.md)'s own kernel-revision sections; see also [OC-008](OC008.md), the case this fix was made for.

Both frozen cases here were re-run under kernel v3 and preserved as **`runs/oc-007-v3-2026-09-10.json`** (primary) and **`runs/oc-007-control-v3-2026-09-10.json`** (control), alongside the original v2-kernel records (`runs/oc-007-2026-09-10.json`, `runs/oc-007-control-2026-09-10.json`), which remain in `runs/` unmodified as **superseded history with identical results** — nothing about the v2 run records is wrong; they simply predate the kernel fix.

- **Statuses, optimum, saving:** unchanged. `search_status: PASS` (primary), `INCONCLUSIVE` (control, same 2-point acceptance-level coverage gap as before — see "Control case outcome" above, reproduced identically under v3); `best_index: 2` (120x4) on both; saving **$9,028.28, 17.863%** on both, bit-for-bit identical to the v2 figures.
- **Per-candidate precision:** across the 9 non-pruned candidates shared between the primary v2 and v3 records, `max_utilization` differs by at most **3.943e-12** and `min_allowed_screening_a` by at most **6.780e-9 A** (both zero at the optimum candidate itself, index 2). The refined-plan table above (baseline 0.5430% shortfall, optimum 0.0000%) is unchanged to displayed precision on both runs.
- **Kernel evaluations:** **15,631,645,536 → 12,574,781,856** (−19.6%), identical between primary and control as before (geometry-only, not material-dataset-dependent). `points_saved_by_pruning` stays 3,776; `estimated_kernel_evaluations_saved` (scaled from the coarse phase's own now-smaller per-point cost) fell from 5,558,646,579.2 to **4,760,357,888.0**.

## What this does not establish

- **Synthetic prices.** Every dollar figure comes from an invented placeholder cost model ($30/m conductor, 10% scrap, $500/pancake assembly, $200/interface joint), not supplier data or a production cost estimate.
- **Screening model.** The physical gate is the OC-004 coupled screening margin under its declared assumptions (homogenized pack, applied-field-as-local-field, period-180/mirror-pair angle policy, no self-field redistribution), never a qualified operating current.
- **No per-candidate independent reference.** Only the frozen OC-004 geometry has an independently generated Python reference; every OC-007 candidate's rerun `numerical_status` is `INCONCLUSIVE` by construction, and `refinement_status` PASS is the check this record relies on instead.
- **OC-004's own reference subset excluded its limiting point.** OC-004's frozen `reference_subset` (18 station/tape/turn combinations, 90 points) does not include OC-004's actual limiting point (`arc_apex`/tape 3/turn 50) — the same point that is this search's own baseline's limiting point. The independent reference validates OC-004's kernel broadly, not specifically at the point this search's baseline depends on most.
- **No width transfer.** `width_transfer.basis` is `none`: no Jc nonuniformity across the tape width or batch variation is modeled, and the coupling relies on a single measured specimen (SP066 / SCS12050-AP M3-1386-3).
- **One specimen.** All conductor data traces to the same single research specimen OC-003 through OC-006 already used.
- **The OC-005/OC-006 multi-axis interpolation limitation carries over unchanged.** The three-axis stratum's worst 25.03% error is an *underprediction* that can inflate material requirements and weaken modeled savings; the 8.64% worst overprediction supports the declared 0.10 `interpolation_overprediction_budget` this search's screening depends on but does not prove a bound on it. See [OC-004](OC004.md)/[OC-005](OC005.md)/[OC-006](OC006.md).
- **Self-field share at low field.** As OC-006 flagged, `mu0*(Ic/w)/(2B)` grows toward and past order 1 at the lowest fields the low-field dataset covers (0.05-0.1 T); this is a screening-model diagnostic, not a demonstrated physical bound. The primary case's own `max_self_field_ratio` diagnostic reached 0.8067 at the optimum (well away from the limiting point, whose own ratio was 0.0117, far under the 0.1 gate that applies there).
- **No mechanics, thermal or quench.** None of these are modeled, unchanged from OC-004.
- **Conductor qualification INCONCLUSIVE; engineering NOT_EVALUATED.** As declared throughout OC-004 and unchanged here.
