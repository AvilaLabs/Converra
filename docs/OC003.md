# OC-003: measured conductor data and interpolation

Implemented September 9, 2026. OptCoil now imports an attributed measured-material CSV, interpolates critical current per width using measured temperature/field/angle coordinates, and tests predictions against withheld measurements. This is a conductor-characterization foundation; overall engineering acceptance remains `NOT_EVALUATED`.

## Run it

```bash
# Reproduce the linear baseline, logarithmic development check and reserved test.
cargo run --release --offline -- material-benchmark --output runs/oc-003.json

# Query the embedded 20–40 K characterization region.
cargo run --release --offline -- material-query \
  --temperature-k 30 --applied-field-t 5 --angle-from-normal-deg 90

# Inspect the actual CSV/metadata import path.
cargo run --offline -- material-inspect \
  data/materials/robinson-superpower-ap-v3/material.json \
  data/materials/robinson-superpower-ap-v3/measurements.csv

# Query an explicit metadata/CSV pair. --json and --output are also supported.
cargo run --release --offline -- material-query \
  --metadata data/materials/robinson-superpower-ap-v3/material.json \
  --csv data/materials/robinson-superpower-ap-v3/measurements.csv \
  --temperature-k 30 --applied-field-t 5 --angle-from-normal-deg 90

# A valid physical query beyond the data produces INCONCLUSIVE, no Ic, exit != 0.
cargo run --offline -- material-query \
  --temperature-k 30 --applied-field-t 20 --angle-from-normal-deg 90 --json
```

Existing report files are protected. The benchmark command exits successfully only when both the logarithmic development case and reserved challenge pass. Its report retains the failed linear baseline. A supported material query exits successfully for its domain/criterion check; this does **not** establish an operating-current allowance. A different electric-field criterion, missing measured coverage or a coverage hole produces no current estimate. Invalid input/units or a mismatched CSV hash is rejected explicitly.

The default query above predicts approximately 200,671 A/m of specimen width, equivalent to 200.67 A for the measured 1 mm bridge. It does not report a 12 mm tape capacity. The CLI prints the source measurement rows and interpolation weights. The desktop remains an OC-001 allocation client; measured-data GUI workflows are future work.

## Source, rights and interpretation

The [SuperPower Advanced Pinning dataset, version 3](https://figshare.com/articles/dataset/Critical_current_characterisation_of_SuperPower_Advanced_Pinning_2G_HTS_superconducting_wire/4256624/3) was measured by Stuart Wimbush, Nick Strickland and Andres Pantoja at the Robinson Research Institute, Victoria University of Wellington. Its individual files are **CC BY 4.0**; [local attribution and changes](../data/materials/robinson-superpower-ap-v3/README.md) accompany the copied data. Converra source is MIT-licensed; the data retains its original license.

The source describes specimen SP066, manufacturer designation SCS12050-AP M3-1386-3, measured January 29–February 3, 2021. A 12 mm tape was laser-patterned to a **1 mm × 5 mm bridge**. The voltage criterion is 0.5 µV over 5 mm, or `1e-4 V/m` (1 µV/cm). Its critical current is extracted from an IV fit. The source workbook and description are archived unchanged, with Figshare file checksums and pinned SHA-256 identities.

The published workbook contains **17,579 measurement rows**. The first declared characterization region contains **1,505 rows** on nominal temperatures 20, 25, 30, 35 and 40 K; nominal applied fields 1, 1.5, 2, 3, 5, 7 and 8 T; and 43 nominal angles from 0° through 180°. Every excluded source row is recorded. Selection was frozen before measuring interpolation errors.

Coordinates use the source's measured `Temperature`, its recommended `Field` estimate, and its recommended `Hall angle`. Setpoints determine grid connectivity only. Within the selected data, actual coordinates differ from commands by up to 0.02 K, 0.001 T and 2.3°. A query exactly on a nominal selection boundary is not automatically inside the measured-coordinate hull.

Published `Ic/w` in A/cm is multiplied by 100 to obtain A/m. The separate published bridge-current column provides an independent rounding-level check on this conversion. Current per width is a characterization quantity, not an intrinsic volumetric `Jc` in A/m².

Angles are oriented from the tape normal: 0° is perpendicular field, 90° is in-plane field under the database's maximum-Lorentz measurement geometry. Full-turn unwrapping follows the commanded angle; there is no reflection folding or inferred 180° material symmetry. The database paper describes its [measurement and angle conventions](https://stuart.wimbush.eu/publications/10.1109/TASC.2016.2628700.pdf). The source's angle convention differs from OC-001's synthetic angle-to-tape-plane convention; the schemas remain separate.

The data uses applied field and includes the measured bridge's self-field response. It cannot silently be used as an intrinsic local current law evaluated at OC-002's total winding-pack field. Measurement uncertainty, strain state and full-width/batch applicability are not quantified here.

## Numerical model

The [Rust interpolator](../crates/optcoil-physics/src/critical_current.rs) constructs a cell only when all eight measured nodes of a nominal grid cell exist and its span limits are satisfied. Six consistently oriented tetrahedra tile each complete cell. Degenerate or inverted measured-coordinate tetrahedra are rejected. Missing-node cells and cells exceeding the allowed spans do not become interpolation coverage.

The linear baseline interpolates `Ic/w` in `(T, B, angle)`. The logarithmic model interpolates `ln(Ic/w)` in `(T, ln(B), angle)`, then exponentiates the weighted value. This allows local power-law field dependence and exponential temperature dependence without fitting global material parameters. It remains an empirical interpolation, with source-coordinate uncertainty and angular-peak resolution limits. Both methods retain the actual measured coordinates.

Barycentric weights form a convex combination; the logarithmic result stays between its supporting node values. This does not make their minimum a guaranteed physical lower bound between measurements. A containment tolerance of `1e-10` in scaled cell coordinates handles floating-point boundary roundoff. There is no nearest-neighbor fallback, physical distance clamp, arbitrary width scaling or extrapolation.

The declared maximum cell spans are 10 K, a field ratio of 2.5, and 10°. They accommodate the predeclared withheld-plane tests. The full 20–40 K model has 1,008 complete cells / 6,048 tetrahedra. Work is limited to 100,000 measurements, 100,000 candidate cells and a 32 MiB CSV. These are implementation bounds, not assertions of accuracy throughout every possible input range.

## Validation design and results

The [original contract](../benchmarks/measured/oc-003.json) was fixed before calculating errors. Entire nominal angle, temperature or field planes are removed from training. Every removed point strictly inside the other two axes' nominal bounds is scored; boundary omissions are declared beforehand and recorded. Unsupported scored points remain in the coverage denominator. Supporting source rows are checked against training identities to prevent leakage.

Each fold requires **100% coverage, at most 10% P95 relative error, at most 20% worst relative error, and at most 20% worst positive relative error**. P95 is the nearest-rank percentile of `abs(predicted − measured) / measured`. These are development limits, not industry standards or a statistical confidence interval.

Every fold above withholds one axis (angle, temperature or field) at a time. [OC-005](OC005.md) withholds all three simultaneously — the direct analogue of an OC-004 query — and stratifies its results by how many axes are off-grid; its checker (`withheld-nominal-planes-measured-coordinate-validation/v2`, benchmark schema `optcoil-material-benchmark/v2`) now also runs the folds in this table, reproducing the same figures shown here.

| Model / withheld coordinates | Scored points | Coverage | P95 error | Worst error | Worst overprediction |
| --- | ---: | ---: | ---: | ---: | ---: |
| Linear / angle planes | 315 | 100% | 5.404% | 19.778% | 10.474% |
| Linear / temperature planes | 410 | 100% | 8.057% | 15.868% | 15.868% |
| Linear / field planes | 369 | 100% | **10.037%** | 11.300% | 11.300% |
| Logarithmic / angle planes | 315 | 100% | 3.237% | **19.967%** | 5.776% |
| Logarithmic / temperature planes | 410 | 100% | 3.468% | 9.393% | 3.959% |
| Logarithmic / field planes | 369 | 100% | 3.114% | 4.911% | 4.911% |
| Logarithmic / reserved 45 K plane | 205 | 100% | 3.172% | 5.667% | 5.667% |

The linear baseline **fails** its original field-plane P95 gate. Its failed result is retained. The logarithmic model was developed after seeing that failure, so its results on those reused folds are explicitly development validation.

Before evaluating the logarithmic candidate, a [separate challenge](../benchmarks/measured/oc-003-challenge.json) was reserved: previously unused 45 K measurements, supported by training planes at 40 and 50 K in an extended 20–50 K dataset. All 45 K rows are excluded from challenge training. The algorithm was fixed before inspecting challenge errors. It passed the same unchanged limits on all 205 eligible points. This is a reserved same-specimen check, not a separate laboratory or batch validation. Default material queries still use the original 20–40 K dataset.

The worst angular development error is close to 20%, despite the much smaller P95. That limitation must remain visible when choosing future sampling and uncertainty budgets. No numerical pass supplies a guaranteed engineering current margin.

A local release run on the Intel Core i3-N305 took approximately 12 ms for the linear case, 11 ms for logarithmic development and 11 ms for the reserved challenge, excluding compilation and JSON export. Reports preserve every prediction, support row/weight, training identity, boundary omission, coverage/error metric, source data, model identity and implementation fingerprint. Forty automated tests pass across the workspace, including mathematical reproduction tests, holes, unit checks, invalid metadata, out-of-domain queries and regression coverage for OC-001/OC-002.

## Reproduce data preparation

Python's standard library is sufficient; no Python package installation or network access is needed once the archived source is present. Use new output directories:

```bash
python3 tools/prepare_oc003.py --output-dir runs/oc-003-reprepared
python3 tools/prepare_oc003_challenge.py --output-dir runs/oc-003-challenge-reprepared
```

Both preparations were checked to reproduce their CSV, metadata and exclusion audit **byte for byte**. The XLSX parser is intentionally specific to the archived workbook. The product's Rust CSV importer requires named SI columns plus provenance metadata with a matching CSV hash; it is not a general Excel parser or a GUI column-mapping workflow.

## Next engineering work

Acquire suitable full-width/batch and uncertainty evidence, or identify an intrinsic current law with an independently checked inversion. These issues must be resolved before substituting this dataset into OC-001's cost search. Mechanical, thermal and protection checks remain additional requirements.
