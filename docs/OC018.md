# OC-018 — hoop-stress mechanical bound (schema v7)

**Status: implemented; the v7mx OC-012 grid is queued behind v6mx.**

## Why

The schema-v4 mechanical screen checks Lorentz *load* — `I_op·B_peak`
in N/m — against a declared bound. Force-per-length is a surrogate:
REBCO conductor limits are published as *stresses* (axial tensile of
order 450–700 MPa for SuperPower-class tape; transverse/delamination
far lower). The v4 screen cannot answer the question a fusion
reviewer actually asks — "what stress does the conductor see, and does
it survive" — because nothing in the record carries MPa.

## The bound

Pressure-vessel mechanics: a conductor under radial Lorentz load
`f = I·B` (N/m) carries hoop tension `T = f·R`. Per strand the load
is `(I_op/s)·B_peak`; the largest tension develops at the pack's
outermost turn radius `R_outer = bend_radius_m + n·radial_pitch_m/2`.
So, per strand:

```
σ_hoop = (I_op / s) · B_peak · R_outer / A_section
```

Two declared case fields make the bound honest rather than
assumed-and-hidden:

- `mechanical.max_hoop_stress_pa` — the allowable stress (Pa). The
  case author's assumption; published REBCO limits differ by direction
  and criterion (5% Ic degradation vs irreversible onset).
- `mechanical.tension_section_area_m2` — the load-bearing
  cross-section associated with one strand. Deliberately declared, not
  derived: winding-pack fill, substrate thickness and support
  structure are all unmodeled, so the case states its load path
  explicitly. A self-supporting winding declares roughly the tape's
  substrate+stabilizer area; a supported winding declares more.

Both-or-neither at validation: a stress limit without its section is
meaningless, and a section without a limit silently does nothing.

`mechanical_feasible` ANDs every declared check (Lorentz load and hoop
stress); a declared check whose inputs never materialized is
infeasible. Each candidate records `hoop_stress_pa` when computable —
the number is in the record whether or not it gates.

## Scale check

For an OC-012-class candidate (~1–2.5 kA, 8–15 T peak at the tape,
R ≈ 0.06–0.09 m, A = 1.2 mm² for a self-supporting 12 mm tape),
σ lands at several hundred MPa to multiple GPa — the bound *bites* at
demo scale and is the binding constraint at fusion scale (the SPARC
TFMC regime, ~822 kN/m, is exactly where this screen matters). That is
the finding the v7mx grid tests: whether the model-informed thin-pack
optima survive a declared mechanical bound, or whether part of the
"75%" was never mechanically feasible.

## Version chain

- Search case schema **v7** (`optcoil-coupled-search/v7`): v6 plus the
  optional `mechanical` hoop pair. Schemas v4–v6 must not declare the
  fields — they change screening semantics.
- Search run record **v6** (`optcoil-coupled-search-run/v6`): adds the
  serde-defaulted `hoop_stress_pa`; v5 records still parse.
- Search model id → `/v6`, checker id → `/v7` (the bump also covers
  OC-017's `transverse_bound` verdict semantics, which had left the
  ids unmoved).
- Acceptance recomputation id → `/v4`: the independent
  `mechanical_agreement_status` recompute applies the same combined
  bound — written out again there, not shared — so an agreement FAIL
  still means a real disagreement, not a missing term.
- The coupled-conductor schema is untouched: the bound is a
  search-level aggregate check on the candidate, not a per-point
  physics change.

## Explicitly out of scope

Still a screen, not a stress analysis: no stress concentration at
ends or joints, no transverse/delamination component, no fatigue, no
support-structure sharing beyond the declared section, no thermal
contraction. `docs/SUPPORTED_DOMAINS.md` lists the standing boundary.
