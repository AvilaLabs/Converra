# OC-002: finite-cross-section racetrack magnetostatics

Implemented September 9, 2026. This benchmark establishes a numerical field-evaluation foundation. It does not establish HTS operating margins, manufacturability, production engineering acceptance or cost savings.

## Run and reproduce

```bash
# Embedded case and independently generated reference; no Python needed to run.
cargo run --release --offline -- field-benchmark

# Preserve all inputs, reference data, field vectors, convergence and identities.
cargo run --release --offline -- field-benchmark --output runs/oc-002.json

# Explicit files, useful when developing a different geometry.
cargo run --release --offline -- field benchmarks/synthetic/oc-002.json \
  --reference benchmarks/synthetic/oc-002.reference.json --json

# Reproduce the independent reference with Python and NumPy, never the Rust kernel.
# The destination must not already exist. Run the first export above to create runs/.
python3 tools/reference_oc002.py --output runs/oc-002-reference-reproduced.json

# Deliberately under-resolve the benchmark: diagnostics remain available, exit != 0.
cargo run --release --offline -- field-benchmark --orders 2,3,4 --json
```

Omit `--offline` only if the Rust dependency cache needs populating. The checked reference was generated with Python 3.14.4 and NumPy 2.3.5. Python is an independent development/reference tool; the product evaluator and CLI remain Rust.

Both field commands exit successfully only for a numerical `PASS`. Missing reference evidence or unresolved convergence yields `INCONCLUSIVE`; a converged comparison exceeding its limit yields `FAIL`. JSON diagnostics and requested new output files are emitted for these completed runs. Malformed inputs, stale references and numerical work-limit errors fail explicitly. Files are never overwritten. The egui app currently opens OC-001 allocation cases; OC-002 is available through the headless API and CLI.

## Frozen case and assumptions

The [case](../benchmarks/synthetic/oc-002.json) fixes geometry, current, probes and limits before tuning. Its exact-byte SHA-256 is `1599be0d1ec5022e2753d500f2850045bb4e5d05bb57f395f56f2c8e2d551ef9`. Do not edit it to recover a passing result; add a separately identified case for a new experiment.

| Quantity | Value |
| --- | ---: |
| Each straight section's length | 0.6 m |
| Centerline bend radius | 0.2 m |
| Radial pack width | 0.02 m |
| Axial pack height | 0.04 m |
| Total ampere-turns | 50,000 A-turn |
| Uniform tangential current density | 62.5 MA/m² |
| Fixed normalization field | 0.1 T |

The racetrack is centered at the origin in the XY plane. The straight runs follow X, with semicircle centers at `(±0.3, 0, 0)` m. Positive current circulates counterclockwise viewed from +Z. The pack occupies radii 0.19–0.21 m about each bend and Z = −0.02–0.02 m. The corresponding straight sections close the current paths with continuous tangents. Geometry stores local radial and axial pack directions explicitly through this canonical construction; individual tape surfaces/orientations are not yet represented.

This is a homogeneous winding pack with prescribed uniform volume current and conventional vacuum permeability `mu0 = 4*pi*1e-7 H/m`. There is no iron, nonlinear material response, superconducting screening, current redistribution or resolved individual turns. The field changes when these geometry/current inputs change. These changes are not yet connected to OC-001's tape-allocation decisions.

All **14 probes** are included: bore center/axis/off-axis, straight-pack center/interior/inner face/edge, a point 0.1 mm outside an edge, arc center/interior/edge, the straight-to-arc junction, an exterior point and a far-axis point. The JSON specifies exact coordinates and meanings. Results are point values of the continuous volume-current field, including at pack boundaries. They are not conductor-volume averages or a search for the winding's global peak field. No probes are excluded.

## Calculation and independent reference

The [Rust evaluator](../crates/optcoil-physics/src/racetrack.rs) directly integrates

`B(p) = 1e-7 ∫ J(s) × (p − s) / |p − s|³ dV`.

It splits the two straights and two curved ends into 64 source cells for OC-002. Separated cells use tensor Gauss-Legendre quadrature. Near cells are split at the observation point's clamped source coordinates. Each resulting octant is divided into three pyramids and transformed with coordinates proportional to `(u, u*v, u*w)`. The `u²` Jacobian cancels the integrable volume kernel singularity. For exterior points close to a surface, geometrically spaced integration panels in `u` resolve the small separation scale; the two transverse pyramid coordinates (`v`, `w`) are geometrically graded the same way whenever a pyramid's dominant axis is a short pack extent (v2, added when [OC-004](OC004.md) exposed under-resolved near-face points that OC-002's own exterior probe set never reaches). A later revision (model id `racetrack-uniform-volume-duffy-gauss-graded-metric/v3`, 2026-09-10, OC-008 contract Stage K) corrected that transverse ratio to compare physical lengths rather than mixing coordinates: for the two curved parts, the ratio's azimuthal extent is in radians while its radial/axial extents are in metres, so v2 formed a ratio that differed from the true physical aspect ratio by the local bend radius; v3 scales the azimuthal extent by the observation point's own radius before forming the ratio. Straight cells, the dominant-axis `u` rule, the kernel and the near-boundary roundoff exception are unchanged; see [OC-004](OC004.md)'s kernel-revision section for the full before/after numbers. No field denominator is clamped and no arbitrary filament radius is introduced.

The [independent Python source](../tools/reference_oc002.py) analytically integrates the axial coordinate first. It then evaluates a **two-dimensional** planar integral using triangular Duffy maps, fixed 16 subdivisions per component and NumPy's independent Gauss-Legendre implementation at orders 24, 48 and 72. It neither calls nor imports the production Rust evaluator. The [NumPy quadrature documentation](https://numpy.org/doc/stable/reference/generated/numpy.polynomial.legendre.leggauss.html) describes the node/weight routine. Both implementations share the same physical Biot-Savart law and geometric assumptions; this is an independent numerical implementation, not independent experimental evidence.

The generated [reference artifact](../benchmarks/synthetic/oc-002.reference.json) preserves all three field vectors and their changes for every probe, source/case hashes, settings, software versions and analytic audit results. The runner checks case bytes, source hash, method, permeability, settings, probe identities, ordering and coordinates before evaluation. It recomputes reference refinement changes from the stored vectors. Hashes identify data and code; they do not authenticate an arbitrary third party's asserted results.

An additional closed-form check collapses the straight length to zero, producing a finite rectangular annulus. With inner/outer radii `ri, ro`, half-height `h/2`, axial observation coordinate `z`, and `F(t) = t[asinh(ro/|t|) − asinh(ri/|t|)]`, with `F(0)=0`, its axis field is

`Bz = mu0 J / 2 * [F(z + h/2) − F(z − h/2)]`.

Rust and Python are each checked against this antiderivative. Further Rust tests cover polynomial moments, all coordinate-reflection symmetries, zero/reversed/scaled current, coincident-source superposition, the far-field dipole limit and continuity approaching straight/curved pack surfaces from both sides.

## Error gates and observed result

All discrepancies are Euclidean norms of vector differences. Normalize by the **fixed 0.1 T case scale**, not the field magnitude at each probe. This keeps absolute errors meaningful at low-field locations. The default production orders are 6, 10 and 14; the final comparison uses order 14 and refinement uses the difference between 10 and 14. Both earlier and later refinement differences are preserved.

| Check | Frozen absolute limit | Observed maximum |
| --- | ---: | ---: |
| Rust vs independent reference | 1e-3 T (1% of scale) | 2.96777e-10 T |
| Rust final refinement change | 2.5e-4 T (0.25% of scale) | 1.570107e-7 T |
| Reference final refinement change | 1e-5 T (0.01% of scale) | 2.17471e-8 T |

All gates passed. These are development thresholds, not industry acceptance standards. The observed Rust/reference difference is smaller than the reference's own observed refinement change: it must **not** be presented as a guaranteed 0.3 nT accuracy bound. Agreement and refinement observations are evidence within this model and probe set; they do not supply a rigorous error certificate or uncertainty budget for an HTS magnet. The case and reference are unchanged from the original OC-002 benchmark (SHA-256 `1599be0d1ec5022e2753d500f2850045bb4e5d05bb57f395f56f2c8e2d551ef9`; independent reference artifact SHA-256 `d67084490bf8af656e67761927afe937ba932b1e5a411987b495e7c9372e0e4f`, itself untouched by every kernel revision below); only the Rust kernel's near-face transverse quadrature changed (see above), which is why the reference's own refinement figure is identical to before while the Rust-side numbers tightened.

**Kernel v3 re-validation (2026-09-10, OC-008 contract Stage K — metric-consistent transverse ratio, see above).** All three gates above are unchanged from the v2 kernel, bit-for-bit: the limiting point for each check (`straight_interior`, a straight-cell probe) is untouched by a fix that only changes how arc-cell ratios are formed. Rust vs independent reference stays **2.96777e-10 T**, Rust final refinement change stays **1.570107e-7 T**, reference final refinement change stays **2.17471e-8 T** (reference untouched, as before). What did change: total kernel evaluations fell from 6,989,400 to **5,817,240** (−16.8%), because the corrected, physically-scaled ratio no longer over-grades arc cells whose ~0.2 m local bend radius is well under 1 — v2's uncorrected ratio treated the (larger, in raw radians) azimuthal extent as if it were a comparably large metre extent, graded more finely than the physical aspect ratio required. Elapsed time fell correspondingly, to **316.6 ms** on one thread (same hardware/profile as below); this is a real reduction in quadrature work, not clock-state noise, since the underlying evaluation count itself dropped.

A release run on the local Intel Core i3-N305, Linux x86_64, pinned Rust 1.95.0, completed all 14 probes and all three production orders in approximately **0.62 seconds on one thread**, with 6,989,400 kernel samples (previously measured at 0.40 seconds with the identical kernel-evaluation count — the difference is CPU clock state on this laptop, which was observed at about 1.1–1.2 GHz of a 3.8 GHz maximum during the slower measurements, not added work — and, before that, 0.24 seconds and 5,405,400 samples with the plain, un-graded kernel — about 29% more kernel evaluations from the added near-face transverse panels). The final order alone took approximately 0.43 seconds. This is an observed small-case timing, excluding compilation, Python reference generation and JSON export; it is not a throughput guarantee or comparison against commercial software. Run records preserve hardware, profile, counts and individual timings. The implementation identity fingerprints the model/kernel/runner sources, Cargo lockfile and toolchain pin bundled at compilation.

## Supported scope and next work

The initial numerical input bounds are dimensions 1e-9–1e6 m, nonnegative straight half-length up to 1e6 m, inner radius at least 1e-9 m, absolute ampere-turns up to 1e12 A-turn, and probe coordinates within ±1e6 m. There are at most 256 probes, 4,096 source cells, quadrature orders 2–24 and 20 million kernel samples per probe per order. These bounds limit invalid/arbitrary work; they do not establish accuracy throughout that entire domain. Unresolved geometry or quadrature returns an error or inconclusive refinement. Validation evidence presently covers OC-002 and the documented regression cases.

Overall engineering status remains `NOT_EVALUATED`. The next substantive work is a traceable measured `Ic(B,T,angle)` dataset with supported domains and uncertainty, a justified relationship between local field and tape orientation/current sharing, and permitted manufacturing changes connected to geometry. Mechanical, thermal and quench acceptance and an appropriate external higher-fidelity comparison remain necessary before claiming production cost savings.
