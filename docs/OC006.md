# OC-006: low-field extension of the measured conductor dataset

Implemented September 10, 2026. OC-004's coupled screening currently falls back to a monotone field lower-bound clamp (A8, clamped at 1.001 T) for any winding-pack region below 1 T, because the embedded `robinson-superpower-ap-v3` dataset carries no measurements there. OC-006 tests whether the same specimen, the same archived workbook, and the same frozen logarithmic interpolator (`measured-coordinate-tetrahedral-log-field-log-ic/v1`) can instead supply interpolated estimates for pack regions between 0.05 T and 1 T, by adding a second embedded dataset — `robinson-superpower-ap-v3-lowfield` — that extends the field selection downward, and validating it with the same withheld-plane methodology OC-003 and OC-005 already used. The original `robinson-superpower-ap-v3` directory is untouched and stays byte-identical; it remains the dataset pinned by the frozen OC-003/OC-004/OC-005 benchmarks.

**Result, stated plainly up front:** two verdicts, reported separately because the frozen benchmark defines them separately. The checker verdict is `interpolation_validation_status` **FAIL**: the `multi_axis_planes` fold exceeds the general 20% worst-error gate at 25.034%, an underprediction at the same 35 K / 7 T / ~90° ab-plane peak already logged as OC-003's worst single-axis error (19.967%) and OC-005's worst multi-axis error (25.034%, identical). The four single-axis folds pass, and `low_field_planes`, whose entire holdout lies in the newly added 0.05–1 T region, passes every gate with P95 1.974% and worst 2.810%. The adoption verdict follows the rule frozen before the run, which keys on the low-field folds: none failed, so a future coupled case may pin this dataset, with the multi-axis limitation, a declared clamp and a declared monotonicity tolerance disclosed. OC-004 itself is frozen and keeps its clamp. See [Consequence outcome](#consequence-outcome).

## Run and reproduce

```bash
# Save a complete run record; use a new output filename for each run.
cargo run --release --offline -- material-validate benchmarks/measured/oc-006.json \
  --output runs/oc-006-<date>.json

# Print the full JSON report without saving a file.
cargo run --release --offline -- material-validate benchmarks/measured/oc-006.json --json

# Query the low-field extension explicitly; --dataset never silently switches.
cargo run --release --offline -- material-query --dataset robinson-superpower-ap-v3-lowfield \
  --temperature-k 21 --applied-field-t 0.3 --angle-from-normal-deg 90 --json

# The same query against the original dataset is INCONCLUSIVE (0.3 T is below its domain).
cargo run --release --offline -- material-query \
  --temperature-k 21 --applied-field-t 0.3 --angle-from-normal-deg 90 --json

# Re-confirm OC-004's coupled screening is unaffected (it still declares the original dataset_id).
cargo run --release --offline -- coupled-benchmark --json
```

`material-validate` exits successfully (0) only when `interpolation_validation_status` is `PASS`. This run's status is `FAIL`, so the CLI exits 1; the full record is still written and printed. `material-query` and `material-validate` both accept `--dataset <id>` (`robinson-superpower-ap-v3` remains the default for `material-query`; `material-validate` defaults to the benchmark file's own declared `dataset_id`, and a `--dataset` that disagrees with it is rejected explicitly before any validation runs — never a silent switch).

## Monotonicity audit on the low-field dataset

`audit_monotonicity` (`optcoil_physics::tape_frame`) is only invoked inside `run_coupled_case`, and OC-006 declares no coupled case (per the contract, one is added only if asked). Per the task instructions, this audit was reproduced from the CSV using the identical algorithm — group by nominal `(temperature, angle)`, sort by measured `applied_field_t`, flag any consecutive pair where `Ic/w` increases by more than a relative tolerance. The reproduction was checked against OC-004's own logged figure before trusting it: restricted to ≥ 1 T, it reproduces OC-004's exact numbers (1,290 pairs, 0 violations, worst relative increase +0.0017%, i.e. 1.70200e-5), confirming methodology fidelity to the Rust implementation.

## Consequence outcome

Two verdicts are reported separately, because the frozen benchmark defines them separately.

**Checker verdict.** `interpolation_validation_status` is **FAIL**. `multi_axis_planes` exceeds the general 20% worst-error gate every fold is held to, at 25.034% (an underprediction at source row 5413, 35 K / 7 T / ~90°); its three-axis overprediction gate is met (8.637% against 0.10). The four single-axis folds pass. `low_field_planes`, the fold whose entire holdout set lies inside the newly added 0.05–1 T region and therefore the most direct evidence for the extension's own accuracy, passes every gate: 100% coverage, P95 1.974% (limit 10%), worst 2.810% (limit 20%), worst positive 0.217% (limit 20%).

**Adoption verdict under the pre-declared rule.** The benchmark description, fixed before the run, states: "a failing low-field fold means the extension is NOT adopted for coupling". No low-field fold failed, so the adoption condition is met: a future coupled case may pin `robinson-superpower-ap-v3-lowfield`. The FAIL traces entirely to a 7 T feature the extension did not touch, reproduced bit-for-bit from OC-005's verdict on the original dataset that OC-004 already pins; treating it as a bar to adoption would indict both datasets equally. Any case pinning either dataset carries that disclosed multi-axis limitation, and the overprediction budget OC-004 depends on is covered by the stratum gate on both. The adoption rule keys on the low-field folds; the overall status is a separate, disclosed verdict and does not override it.

**What adoption does not license.** A case pinning this dataset must declare, citing this benchmark and its audit as evidence: (i) its own low-field clamp value at or above 0.05 T and its monotonicity tolerance, because the audit below finds 3 of 3,010 pairs above 0.1% (worst +0.182% at 25 K, 0.05 → 0.07 T), so OC-004's 0.1% tolerance would fail on this dataset and disable every lower-bound point; (ii) that the self-field share `mu0·K/(2B)` reaches order 1 or more below about 0.15 T, so estimates there are screening inputs at non-limiting points, not a validated local law, with OC-004's self-field gate on the limiting point still applying. The interpolator is not tuned on this result.

## Interpretation

- **The low-field region itself interpolates well.** Every fold whose worst point lies in the newly added 0.05–1 T range (`low_field_planes`, and the lower half of `field_planes_full`) stays well inside every gate, with errors comparable to or better than OC-003's original ≥ 1 T folds (e.g. `low_field_planes`' 2.810% worst vs. OC-003's field-plane fold's 4.911% at ≥ 1 T — the same 4.911% number reappears here as `field_planes_full`'s worst, since that fold's holdout also includes the original ≥ 1 T interior planes).
- **The FAIL is inherited, not introduced.** Source row 5413 was already the single worst logged error across OC-003 and OC-005, at a temperature/field/angle combination nowhere near the low-field extension. Its numbers here (relative error, predicted value, support structure) are identical to the earlier documents' figures, confirming the low-field data did not perturb its supporting cell.
- **A genuine low-field limitation does exist, but it is a different one: the self-field share.** See Limitations below — the extension's own interpolation accuracy is not the binding concern at the very lowest fields; the applied-field/self-field separation the whole dataset (original and extension) relies on is.
- **Same specimen, development validation.** All data is SP066/SCS12050-AP M3-1386-3, the same specimen OC-003/OC-004/OC-005 already used; this is not an independent-batch or reserved-sample test.

## Limitations

- One research specimen (SP066): a 1 mm patterned bridge, not a manufacturer batch guarantee or full-width 12 mm tape qualification (`dataset.metadata.limitations`).
- **0–0.03 T excluded.** Below 0.05 T the unwrapped Hall angle drifts far enough from the commanded angle (up to 9.03° at 0.01 T, 55.9° stdev at 0 T) to risk inverting measured-coordinate tetrahedra at this dataset's ~2° nominal angle spacing; 0 T is additionally undefined under the logarithmic (`ln B`) model. These field levels are not represented at all — not by this dataset, not by OC-004's clamp (which applies only above its own 1.001 T floor), and not by any interpolation this repository performs.
- **Self-field share grows large at the lowest fields still included.** Using the measured `Ic/w` itself as the upper-bound sheet current `K` (i.e., the self-field a conductor actually carrying its full interpolated critical current would produce), `r = mu0·K/(2·B)` at a representative point (30 K, 90°, measured coordinates ≈ nominal):

  | Nominal B (T) | Ic/w (A/m) | mu0·K/(2B) |
  | ---: | ---: | ---: |
  | 0.05 | 314,757 | **3.955** |
  | 0.07 | 313,381 | 2.813 |
  | 0.1 | 312,702 | 1.965 |
  | 0.15 | 310,000 | 1.299 |
  | 0.2 | 307,309 | 0.965 |
  | 0.3 | 301,160 | 0.631 |
  | 0.5 | 288,716 | 0.363 |
  | 0.7 | 277,567 | 0.249 |
  | 1.0 | 264,856 | 0.166 |

  At the two lowest included levels the ratio exceeds 1 (0.05 T) or approaches it (0.07 T): a conductor actually operated near its interpolated critical current there would generate self-field comparable to or larger than the applied field itself, which is a far stronger violation than the small 0.1 ratio OC-004's own A3 diagnostic treats as a caution threshold at its much higher-field operating points. This is illustrative at one representative `(T, angle)` slice, not a worst-case scan — at other temperatures/angles `Ic/w` and therefore this ratio would differ. It means the applied-field coordinate this whole dataset uses cannot be assumed to approximate the local field a real conductor sees anywhere near 0.05–0.1 T, independent of whether the interpolator itself scores well there.
  - **Monotonicity is not uniformly clean at the lowest included field.** 3 of 3,010 checked pairs violate OC-004's own 0.1% tolerance, all at the 0.05 T → 0.07 T step, all at 25 K, worst +0.182% — small but consistent with a weak secondary-peak feature, not noise. See the audit above.
- Applied-field transport data includes the specimen's self-field response; no intrinsic local `Jc(B)` law or coupling to OC-002 is established by this benchmark.
- Maximum Lorentz-force angle geometry only; no reflection symmetry, arbitrary azimuth or extrapolation is assumed.
- This is a withheld-plane development validation on one specimen, not a statistical confidence interval or a guaranteed lower current bound.
- Measurement uncertainty and strain state are not quantified; engineering current margins, thermal, mechanical, quench and manufacturing acceptance remain `NOT_EVALUATED`.

## Next engineering work

OC-004 is frozen and keeps its clamp; the extension is adoptable by a future coupled case under the pre-declared rule. Before a case pins this dataset:

- **Resolve the self-field-share limitation, not just the interpolation-accuracy one.** Even where `low_field_planes` passes cleanly, the applied-field/self-field separation this dataset (and the whole `measured-coordinate-tetrahedral-log-field-log-ic/v1` approach) relies on becomes questionable at the lowest included fields (`r` of order 1 at 0.05–0.1 T at a representative point). A low-field coupling would need either a demagnetization/self-field correction or a declared, checked bound on where the applied-field approximation is still acceptable.
- **Investigate the 25 K, 0.05 T → 0.07 T monotonicity violations directly**, rather than only auditing them: are they a genuine secondary-peak (fishtail) feature at this specimen's lowest included field, or workbook/measurement noise near the Hall probe's own low-field floor? This bears on whether any future low-field clamp policy needs its own floor distinct from OC-004's 1.001 T value.
- **Revisit the 35 K/7 T ab-plane peak specifically** — now responsible for the worst logged error in OC-003 (single-axis, 19.967%), OC-005 (multi-axis, 25.034%) and OC-006 (multi-axis on the extended grid, 25.034%, identical) — with additional measurements or a locally refined interpolation cell. This feature, not the low-field extension, is what currently prevents both OC-005's and OC-006's multi-axis folds from passing outright, and it sits at 7 T, nowhere near the region this benchmark was meant to extend.
- **Declare the pinning case's low-field clamp and monotonicity tolerance against this benchmark's audit**, and its self-field-ratio treatment below 0.15 T, before running it; a PASS on the low-field folds here is evidence for interpolation accuracy only.
