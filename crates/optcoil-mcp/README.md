# Converra local MCP server

`optcoil-mcp` exposes the same Rust study operations used by the GUI through the
official Rust MCP SDK. It communicates over stdio and persists only under an
explicit local workspace directory. It has no remote listener or hosted account.

## Setup

Download the platform's CLI/MCP archive from
[GitHub Releases](https://github.com/AvilaLabs/Converra/releases/latest) and extract
`optcoil-mcp` (`optcoil-mcp.exe` on Windows). No Rust installation is needed.
Alternatively, build from the repository root:

```bash
cargo build --release -p optcoil-mcp
```

Configure an MCP client with the absolute executable path and a dedicated study
directory. A typical client configuration is:

```json
{
  "mcpServers": {
    "converra": {
      "command": "/absolute/path/to/optcoil-mcp",
      "args": ["--workspace-dir", "/absolute/path/to/my-converra-study"]
    }
  }
}
```

On Windows use the absolute `optcoil-mcp.exe` path. Client configuration formats
vary; the process command and arguments stay the same. The directory is created
if missing, with `workspace.json` and an `exports/` directory. Run one server
process per directory. Standard output is reserved for protocol messages.

## Tool workflow

| Step | Tools |
| --- | --- |
| Discover supported models, verdicts and limits | `engine_capabilities`, `list_datasets` |
| Create or import a study | `create_study`, `import_study` |
| Supply exact inputs and dependencies | `create_variant`, `revise_variant`, `attach_dataset_bundle` |
| Organize alternatives | `list_variants`, `select_variant`, `duplicate_variant`, `rename_variant` |
| Check inputs, decisions and unresolved gates | `preflight_variant`, `summarize_variant`, `diagnose_variant` |
| Calculate | `start_search`, `start_sensitivity`, `start_robustness` |
| Declare and review scenarios | `preview_robustness`, `list_robustness_results` |
| Follow progress or cancel | `get_job`, `cancel_job`, `get_job_result` |
| Inspect evidence | `list_results`, `compare_variants`, `verify_result` |
| Propose an unevaluated next experiment | `propose_follow_up` |
| Export portable evidence | `export_review_package` |

`create_variant` accepts `name`, a `case_json` string, optional
`dataset_bundles` containing raw bundle JSON strings, and optional `threads`.
Inputs use the engine's case and material schemas. Do not normalize signed
bundle files: their exact source bytes are retained. Thread overrides may reduce
the declared case limit.

Search, sensitivity and scenario calls return a job ID promptly. Poll `get_job` until
`completed`, `cancelled` or `failed`; a cancellation request is not completion.
Workspace mutations are paused during a calculation. Completed searches attach
verified source records atomically to the persistent study. Failed or cancelled
jobs leave previously completed evidence available.

Search job summaries explicitly report `reused_calculation` when an unchanged
input uses a verified result from the live engine session. The original source
record and calculation timestamp are retained.

Tools return compact JSON or artifact locators. Use MCP `resources/read` for
full inputs, records and exported artifacts. Resource URIs are generated by the
server, for example:

```text
optcoil://study/workspace
optcoil://study/variant/<variant-id>/case
optcoil://study/variant/<variant-id>/result/<result-id>
optcoil://study/robustness/<record-sha256>
optcoil://artifact/<export-id>/manifest.json
```

Read `optcoil://study/workspace` to obtain a GUI-compatible saved study. Importing
that study retains its historical evidence but does not populate the running
engine's result cache. The server's execution cache contains only calculations
performed and verified in the current process.

The server also exposes `optcoil://examples/first-study` as a read-only resource.
It returns the versioned `first-study.json` case; reading it does not add it to
your workspace or start a calculation. The example is based on OC-007 geometry
and uses the attributed `robinson-superpower-ap-v3-lowfield` dataset, an
adaptation of Robinson's measured SuperPower AP data (see the
[dataset attribution and preparation notes](../../data/materials/robinson-superpower-ap-v3-lowfield/README.md)).
It illustrates a 21 K, 0.05 T racetrack study that transfers the measured bridge
law to a 12 mm tape width under the assumptions declared in the case. Its prices
are invented teaching placeholders: USD 30/m of tape, USD 500 per pancake, and
USD 200 per interface. They are not supplier quotes. The example is a bounded
screening exercise and does not establish engineering acceptance.

## Explicit scenario analysis (source builds)

`preview_robustness` and `start_robustness` accept selected `variant_ids` and
`spec_json` using `optcoil-robustness-spec/v1`. A nominal row is mandatory. Named
what-if rows declare dataset-specific price and Ic multipliers and a temperature
offset. The engine preserves the original numerical gates and rejects
incomparable requirements or operating contracts. Scaled conductor data is
explicitly synthetic; no probabilities or measurement uncertainty are inferred.

Completed scenario jobs attach full replay evidence to workspace v2, including
source cases, material bundles, transformed inputs and calculation records.
`list_robustness_results` returns compact winners, changes and current/history
bindings with full-record resource locators. Resources survive server restart;
up to three analyses fit within the workspace payload limit. Cancelled jobs do
not attach partial evidence. See [scenario studies](../../docs/ROBUSTNESS.md).
These tools were added after v0.2.0 and ship from v0.3.0.

## Limits and result meaning

`engine_capabilities` reports the enforced limits: one engine job at a time,
bounded candidate/work estimates, sensitivity points, job history, input sizes
and a 15-minute cooperative calculation budget. Oversized inputs and unsupported
operations return errors; they do not silently relax numerical or engineering
gates. Use smaller explicitly declared studies when a limit is exceeded.

Full records preserve `PASS`, `FAIL`, `INCONCLUSIVE` and `NOT_EVALUATED`. Preflight
readiness and a screening pass do not establish engineering acceptance. Offline
verification checks source bindings and ledgers, not independent physics
accuracy. Follow-up proposals are uncalculated inputs until you create a new
variant and run it.

`export_review_package` writes into a fresh directory under `exports/` and
returns artifact resources. Verify the package with:

```bash
optcoil verify-package /absolute/path/to/my-converra-study/exports/<export-id>
```

## Verification

```bash
cargo test -p optcoil-mcp
```

Integration tests use an actual SDK client and child-process stdio server for
discovery, schemas, calls, errors, progress, cancellation, persistence and
resource access. The GUI, CLI and MCP all call the shared headless engine.
